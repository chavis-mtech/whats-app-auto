# Live acceptance checklist

This is the remaining manual acceptance boundary. The build and automated demo checks do not prove real WhatsApp pairing or delivery. Perform these steps only with a dedicated approved account and explicitly approved synthetic test recipient/group. Never reuse an HR linked-device session or real HR records.

1. Extract the full portable release and Start.cmd. Confirm browser opens `http://127.0.0.1:4318`; set a password. Demo mode should be visible. Try synthetic text and a small file before changing mode.
2. Save live mode and the expected international account digits. Confirm all demo destinations/messages/jobs disappear, and nothing connects or sends automatically.
3. Click Connect. Scan the private QR from the phone's Linked devices page using exactly the configured account. Verify account digits and connected status. If mismatch is reported, first check national/international formatting and the actual phone account; correct the setting and retry with the existing session. Reset/unlink only if intentionally replacing the linked account/session. A raw LID must never pass the phone guard.
4. Refresh groups. Verify the approved group name and actual JID against the phone. Contacts must be labeled synced/observed, with no full-phonebook claim. Allow only the test recipient/group.
5. Send a unique marker, for example `Synthetic live acceptance 2026-11-21 <unique-id>`, and a synthetic small document. Verify message/file content on the destination's phone. A submitted result alone is insufficient. Observe any delivery/read update without assuming it must appear.
6. Reveal a local API token privately. POST a unique synthetic `/send` with an Idempotency-Key. Repeat the exact request/key; confirm one app receipt and one WhatsApp message. Change content under that key; confirm 409 and no second message.
7. Create a paused one-minute interval task, preview it, then enable. Verify one intended message when due. Pause after one run. Create a one-time task and a daily task in the intended timezone, using a near-future approved time.
8. Create a separate approved inbox source and destination. Save an inbox task, send new synthetic incoming texts from another participant, and verify oldest-first batching. Own messages/history must not echo. A task with equal source and destination must be refused.
9. Add an exact public JSON hostname, preview `{{json.field}}` data, then send to the test destination. Verify invalid JSON, redirect and private/local network sources fail before provider submission.
10. Disconnect internet, observe bounded reconnect, restore internet and check connection. Do not repeatedly click send if the outcome is unknown. If intentionally testing interruption, inspect the actual destination before any manual retry. A persisted interrupted submission should become unknown and never auto-replay; its task should pause.
11. With automatic resume off (the default), stop/restart and confirm WhatsApp remains disconnected until manual Connect. Then reconnect the approved expected account, enable automatic resume in Settings, stop/restart and confirm the same registered account resumes without QR. Enable only an approved test job and verify missed intervals coalesce instead of bursting. Confirm Disconnect disables automatic resume across the next restart; local session reset/account change must also disable it. An expired session must require manual pairing, never unattended QR.
12. If wanted, enable automatic resume for the confirmed account, use Install-Background.cmd then sign out/in. Confirm the local process resumes the existing account and only already-enabled approved jobs can send after connection. No initial pairing or fallback account is allowed. Uninstall-Background.cmd and Stop.cmd should remove registration/stop only the exact app process. Private state remains; Stop preserves opt-in, so use Disconnect or pause jobs to stop future unattended sends.

Record the app version, Windows version, Baileys version, account/recipient authorization reference (without secrets), tested cases and observed results. Do not include QR images, API tokens, passwords, `state.json`, `auth` contents or real chat content in a shareable report.
